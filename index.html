Connecting…

Operating sequence

This independent research workbench (not an ODrive Robotics product) commissions, configures, controls and monitors two ODrive Pro boards over USB. The Test Motor runs in speed control; the Load Motor, always sensored, applies opposing torque through the chain. Only real board data is shown: a disconnected or unsupported signal reads Unavailable. Starting the app, opening or refreshing a page, or recovering from an error never connects to a board or starts a motor.

  1. Configuration → Discover. Find both boards by hexadecimal serial number, assign Test Motor and Load Motor, then confirm the physical roles on Connections. Enter the validated rig limits and the chain coupling there, and connect.
  2. Configuration → Settings. Read each board's configuration. To change a setting: enter the new value, Preview, check the board identity and before/after values, then Apply (each value is read back). Save to the boards only when you mean to keep the change; they reboot, then Reconnect and verify.
  3. Configuration → Calibration. Motor calibration, then encoder offset calibration, one motor at a time, after confirming every safety condition. Then do the hand-turn direction check.
  4. Dashboard. Live values for both motors. Start/apply a speed and an opposing load in N·m or A, set the load to zero, or stop both.
  5. Test Matrix. Load a CSV, preview and save it, check readiness, then Run Selected Test or Run All Selected Tests. Pause After Current Test, Retry or Skip a failed test, or Stop Both Motors and Cancel.
  6. Motor Monitoring. Two columns of live values and graphs; the display can be paused or re-zeroed without touching acquisition.
  7. Results. Process the steady-state captures and compare raw and residual current ripple against speed at each load, sensored against sensorless.

Stop Both Motors (menu bar, every page) requests IDLE on both boards. Torque is removed and the motors coast. It does not brake, cannot stop a mechanical fault, and is not an emergency stop; keep the physical emergency-stop circuit within reach. The boards' watchdogs remove torque on their own if this computer stops communicating while a motor is running.

Sensorless operation is documented as experimental in ODrive 0.6.x firmware. The app starts a sensorless test only after you have commissioned it manually and confirmed it, the test board is already configured for the sensorless estimator, and a verified chain coupling lets the handover be confirmed against the load encoder. Changing a board's feedback source is always a manual Configuration step. Firmware updates are not performed here; see Configuration → Identity.

ODRIVE CONFIGURATION

Configure, calibrate and back up both ODrives

Every write follows the same path: enter values, Preview (board identity with exact before and after values), Apply (each value read back), then optionally save to the boards (they reboot) and Reconnect and verify. Only documented, allowlisted settings can be written, and nothing is written while a motor is moving or a test is recording.

1. Discover and assign boards

Lists the serial numbers of ODrives visible on USB for two seconds. It does not open a connection, read settings or move anything. Close the official GUI and odrivetool first. Label each physical board with its serial number.

Assigning a role saves the serial number in this computer's connection profile only, and clears the “roles verified” confirmation. Re-check the physical wiring and re-confirm it on the Connections page, then connect there.

2. Identity, firmware and faults

Clearing errors is only possible while both boards are IDLE, and it never restarts a motor. Fix the cause first.

Firmware updates are not performed by this app. An update erases the board's configuration and calibration and needs the ODrive DFU tooling. Take a backup (section 5), then use the official Web GUI's Firmware Update tab or odrivetool new-dfu, following the ODrive firmware update guide. This workbench supports released 0.6.x firmware from 0.6.10, with the same version on both boards.

4. Supervised calibration
One motor at a time. Both boards must be connected, IDLE and fault-free. The calibrated motor is energised. During encoder calibration it turns in both directions, and the chain turns the other motor with it. Stop Both Motors in the menu cancels a running calibration.
Direction check (no power applied)
  1. With both boards IDLE and faults cleared, open Motor Monitoring.
  2. Turn the test-motor shaft slowly by hand in its intended forward direction.
  3. Check that the test-motor speed and position rise with the sign of the Test direction setting, and that the load-motor reading changes by the expected coupling ratio and sign.
  4. Record the result with the role, direction and coupling confirmations on Connections.


5. Backup and restore
A backup stores every allowlisted setting of both boards as JSON on this computer (recordings/config-backups) and downloads a copy. Calibration results are not restored. Restoring uses the same preview → apply → read-back path.

The watchdog removes torque if communication stops. The test motor needs velocity control with a speed ramp; the load motor needs torque control with a torque ramp.
